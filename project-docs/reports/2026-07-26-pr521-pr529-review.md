# Review: PR #521 vs #529 (migrate/rollback fixes on the state-engine-pr1 chain)

Reviewer: Claude (PM/review role). Not merged — findings below, decision needed.

## TL;DR

**#521 is fully superseded by #529 — nothing to salvage from #521 separately.**
**#529 should NOT be merged as-is: its own test suite has 4 failing tests, one of which is the exact rollback scenario the PR claims to fix.** It also bundles a large, unreviewed rearchitecture that goes well past its stated scope.

## 1. #521 is a strict subset of #529

Both PRs' stated tasks ("fix slug todo story ids" for #521, "fix migrate rollback against real DB_PATH" for #529) turned out to share a git history, not just similar content:

```
db4fbde (shared base, "wire todo story backfill into migrate")
   └─ 13f4484 "fix: accept slug todo story ids"      ← #521's HEAD
        └─ 6b782fb "fix: rollback migrate against real DB_PATH"  ← #529's HEAD
```

`git merge-base --is-ancestor 13f4484d 6b782fb2` confirms #529's branch was built directly on top of #521's commit. #529 = #521 + one more commit. There is no divergence, no conflict to resolve — #521 can simply be closed in favor of #529.

(Correction to my earlier triage message: I initially read a `git merge-tree` conflict signal between the two branches using the wrong base commit, which suggested they were independent and conflicting. They aren't — #529 is a linear descendant of #521.)

## 2. Both PRs carry ~2,100 lines that aren't about migrate/rollback at all

17-18 files changed in each, but only 2 files and ~75 lines are the actual bug fixes (`synlynk/db.py` + one test file, twice). The rest is a DB-source-of-truth rearchitecture that neither PR's description mentions:

- `roadmap.md` / `costs.md` become generated views of DB tables (`_generate_roadmap_md`, rewritten `update_costs()`)
- New doc rotation/archiving (`_rotate_project_doc`, `docs/archive/INDEX.md`)
- New hand-edit detection (`_detect_hand_edit`) wired into `generate_context()`
- New `synlynk roadmap add` CLI command + full argparse wiring
- `check_budgets()` now reads `cost_entries` (DB) instead of `parse_costs_md()` (the `.md` file) — a real behavior change to budget enforcement
- `scripts/convert_roadmap_table.py` — a new standalone script

This matches `docs/superpowers/plans/2026-07-25-state-engine-pr1.md`, which is a real, approved plan (per Design→Plan→Build in CLAUDE.md) — so this isn't rogue scope creep, it's legitimate plan work. But it is **plan work that has never been reviewed or merged on its own**: the individual task PRs that were supposed to carry it in isolable pieces (#497, #500, #503, #506 — Tasks 1/3/4/6) are all now closed as "absorbed" into this chain, without ever landing on `main`. Right now the *only* place this rearchitecture exists is bundled inside a PR nominally about a migrate bug fix. If #529 merges, the state-engine rearchitecture merges with it, unreviewed as its own unit.

## 3. #529's own test suite doesn't pass

Checked out #529's head (`6b782fb2`) into a scratch worktree and ran the full suite (no CI ran on this branch — `gh pr checks 529` reports "no checks reported"):

```
4 failed, 1395 passed, 2 skipped in 91.90s
FAILED tests/test_agent_quota_tracking.py::test_synlynk_selftest_live_clobbers_real_repo
FAILED tests/test_selftest.py::test_live_selftest_bespoke_lifecycle_scenarios_pass
FAILED tests/test_selftest.py::test_live_selftest_migrate_imports_real_rows
FAILED tests/test_selftest.py::test_scenario_migrate_failure_injection_triggers_rollback
```

The last one is notable: `test_scenario_migrate_failure_injection_triggers_rollback` is the exact rollback-on-failure scenario #529 sets out to fix, and it's still failing on #529's own branch. Failure output shows `.synlynk/state.db already exists, no checkout` and `error: could not restore untracked files from stash` — the rollback mechanism itself appears to still be broken, or the fix is incomplete relative to the test's real invariants. This is the same "job self-reports done but the test suite disagrees" pattern already logged in memory for #202/#461/#496 — worth verifying independently rather than trusting the job's own completion status, which I did here rather than take the PR description at face value.

## Recommendation

1. Close #521 as superseded by #529 (no unique content).
2. Do not merge #529 yet. Two separate problems need separate resolution:
   - The migrate/rollback fix itself needs another pass — the failing rollback test suggests the root cause isn't fully fixed. This should go back through `superpowers:systematic-debugging` rather than a second guess-fix.
   - The state-engine-pr1 rearchitecture (roadmap/costs-as-generated-views, `roadmap add` command, budget-check source change) should land as its own reviewed PR against `main`, not smuggled in as a side effect of a bug-fix branch. Worth deciding whether to extract it from #529's diff into a fresh branch, or re-dispatch it cleanly against current `main`.
3. Given #497/#500/#503/#506/#518/#521 are now all closed and only existed as intermediate commits in this chain, the `state-engine-pr1` plan's actual mergeable artifact is currently nowhere but #529 — worth confirming that's acceptable before more of this plan's task PRs get dispatched, or the same absorption problem will repeat.
