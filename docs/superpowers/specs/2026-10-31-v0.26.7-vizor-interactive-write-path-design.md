## 1. Decision

v0.26.7 is the Vizor write-path edition. It does five committed things, then keeps a dive list for work discovered while the milestone is open:

1. **Sweep the shipped Vizor surface** and classify every view as live-write, write-stub, or read-only. Wire stubs that already have a handler in `synlynk/viz/server.py` through the machine-scoped daemon. New writes go through a single `authorize_local_request` call site into `state.db` (or a documented sidecar). GOVERNS stage edits are **locked by default**. Writes are `/w/<slug>/api/*` only.
2. **Repair secondary and cross-view links** so chrome and iframe stay in sync, and so topology switchers stop 404ing (#4967).
3. **Make Gantt a Gantt (agentic-native):** GOVERNS stages are fixed-width columns; sub-tasks are rows; occupying cells show fill volume; names do not overflow (#4968). Adopt Jantt *learnings* as #4970–#4972 (cell semantics, live summary cards, row virtualization). Do not vendor Jantt.
4. **Fence Hub ephemerals** so `job-*`, `djob-*`, `coldtest`, `chore-local-*`, and other non-durable entries do not appear as workspaces. Registry `kind` + `path_root`, not a slug-prefix list. Wave A hides them; Wave C stores the metadata (`dec-2802c17e`).
5. **Keep a dive list** for the rest of Vizor (World, Product brainstorm files, Journeys, Settings/FTUE, Graphify inspect, Logical detail-on-expand, sentinel HUD). Pick those up while the milestone is in flight; they do not all have to ship in the first implementation PR.

**Jantt is a benchmark, not a dependency** (`dec-144d1e68`). Wave B (#4968) plus learnings #4970–#4972 ship even if Jantt is never vendored. Do not add `@jantt/core` or `@jantt/standalone` to this edition. A later calendar projection (only for rows that already have real ISO `start`/`end`, never synthesized) is out of v0.26.7. Stored GOVERNS edges / CPM / slack / baselines are #4973 (later enhancement).

This edition is a **per-workspace local dashboard**. It does not ship a multi-workspace activity rollup, cost aggregation, or CLI-service parity (`viz --ensure`, daemon lifecycle, identity). Those are named deferred, not silently solved (`dec-2802c17e`).

## 4. Cross-view links (#4967)

### Bug

1. Topology switchers in `synlynk/viz/canvases.py` hardcode `href="/tube.html"` (and `/logical.html`, `/product.html`, `/infra.html`, `/world.html`, `/board.html`, **`/timeline.html`**). Those paths are not workspace-scoped. Live 404.
2. Overview / Activity / Tube use relative `href="gantt.html"`. The iframe navigates; parent `setView` never runs; crumbs and sidebar stay on Overview.
3. `/timeline.html` is not a view. The page is `gantt.html`.

### Fix

- One link helper: given slug + view id, produce `/w/<slug>/<view>.html` **and** a click handler that calls `parent.setView(viewId, src, cat, label)` when `window.parent !== window`. Fallback: full navigation to chrome `index.html` with `?view=`.
- Replace `/timeline.html` with Gantt everywhere.
- Do not use site-root `/tube.html`.
- Tests: for each cached HTML view, every in-app `href` that is not `https:` / `mailto:` / `target=_blank` GitHub resolves to HTTP 200 on the live daemon (or a documented 501 stub). Include the 404s above as regression fixtures.

Out of this ticket: brainstorm file serving, Settings alerts. Hub ephemeral cards are Wave A/C (section 1 item 4), not a dive leftover.

## 5. Gantt layout (#4968)

### Bug

`renderDrill` / `renderTask` in `synlynk/viz/gantt.py`:

- Grid is `260px repeat(N, 1fr)` where **N is task count**.
- Task names become **column headers**.
- Each row is one absolutely positioned bar (`left: index/N`, `width: 0.85/N`) with `white-space:nowrap`, so labels overflow the cell.

Overview rows still use `start_frac` / `width_frac` as a stage strip across `repeat(10, 1fr)`. That is a stage ribbon, not a task Gantt.

### Fix

- **Columns** = GOVERNS stages of that release/milestone. **Fixed column width** (px, not `1fr` that collapses). Horizontal scroll if stages exceed the viewport.
- **Rows** = stories / sub-tasks (one row per task, name in the 260px label column, truncated with tooltip for the full id/title).
- **Cells** = fill volume for the stage that task occupies (done / active / queued / blocked). Fill is a bar *inside the cell*, not a label overflowing into the next stage. Empty stages for that task stay empty.
- Overview ribbon can stay as a collapsed summary; expanding a release shows the row Gantt, not the inverted task-as-column drill.
- Payload stays GOVERNS-only (`view_embed` keys already on Gantt). Do not re-embed `workspace_views.logical`.

Pencil notes and lock-by-default stage edits are write-path (section 6), not this layout ticket.

Jantt is **not** the layout fix and is **not vendored** in this edition. It is a calendar CPM benchmark. Learnings to take into synlynk Gantt are section 5.1.

## 6. Write-path sweep

### Policy

- Every POST goes through a **single** `authorize_local_request` call site. Fail closed. Do not inline the token compare in handlers (`dec-be95cbbf`).
- **Workspace-relative writes only:** `/w/<slug>/api/*`. Site-root POST is not the contract. Today's Gantt `fetch('/note')` hitting `http://127.0.0.1:33333/note` (404) is the cautionary example, not a precedent. Change the client (or a slug-injecting shim) so the request is `/w/<slug>/api/note`. Do not add a second global API.
- Bind stays `127.0.0.1`. `daemon.token` never leaves the node. Cookies stay forbidden.
- GOVERNS stage/date edits: **locked by default**. Unlock is an explicit control. Commit is transactional `roadmap update` into canonical `state.db`. No silent local JSON as the source of truth for stages. A logged-in future caller does not skip the lock.
- Notes may keep `.synlynk/viz-notes.json` (`VIZ_NOTES_PATH`) if that remains the existing contract — document it. Do not invent a second notes store.
- Sentinel CTAs (#2672) stay **out of v0.26.6's read-only lock** until that issue's own write-path spec. This edition *hosts* that work; it does not silently turn the Overview panel into a writer.
- Personal GitHub tokens stay off-limits. Role App tokens only. Human Account roles (synlynk.com) never stand in for `merge_authority`.

## 12. Future evolution: hosted and remote seams (`dec-be95cbbf`)

Non-implementing. No new endpoints, auth modes, or registry population in this edition. Local Hub stays a **machine index**. These bullets exist so hosted Vizor (synlynk.com Phase 1–4, spec `docs/superpowers/specs/2026-10-23-synlynk-com-platform-vision-design.md`) is the same node behind an adapter, not a fork.

1. **Workspace-relative addressing only.** All writes under `/w/<slug>/api/*`. No site-root routes.
2. **Replaceable `authorize_*` seam.** `authorize_local_request(headers) -> (ok, status, message)` is the only call site. A later adapter may accept a short-lived Application credential. The node never receives a personal GitHub token. Cookies stay forbidden. Bind stays `127.0.0.1` on the node; a reverse proxy/relay sits in front of the still-loopback daemon on a VPS/Fargate task.
3. **Registry `kind` + stable-id seam.** Reserve, unset in this edition except as needed for Hub fencing: `kind` (`local` / `hosted` / `ephemeral`, with durable vs ephemeral as the live filter), `path_root`, `node_origin`. Slug is the route key. Existing `product_id` is the stable local id. ARNs (`synlynk:account/…:workspace/<id>`) are not stored in `state.db`. Hub shows durable only — the same fence covers local junk slugs and later Phase 4 swarm nodes.
4. **Node-local telemetry, never a bus.** SSE/heartbeat stay per-node (`/w/<slug>/api/daemon/stream`). Hosted aggregation polls or relays; it does not publish into a shared channel.
5. **Non-negotiables.** Never bind `0.0.0.0` with the local token. Never put `daemon.token` in the browser. Never skip lock-by-default for an authenticated-but-remote caller. Never merge two `state.db` files. GOVERNS agent roles stay orthogonal to human Account/Org/Workspace roles. A `kind=local` Hub card opens `http://127.0.0.1:<port>/w/<slug>/…`; a future `kind=hosted` card deep-links to the owning node. Phase 3 relay pairs cloud to local files/models; it does not copy databases.

Leave to synlynk.com phase specs: Phase 1 membership, Application credentials, ARN parent edges, GitHub login adapter; Phase 2 TLS edge, credential injection, EFS placement of `state.db`, idle teardown; Phase 3 relay pairing; Phase 4 swarm provisioning; the Account dashboard UI.
