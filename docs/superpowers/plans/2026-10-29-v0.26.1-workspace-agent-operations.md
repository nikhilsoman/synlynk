# v0.26.1 — Workspace-agent charter and role operations Implementation Plan

## Overview

This implementation plan operationalizes the architecture specified in `docs/superpowers/specs/2026-10-29-v0.26.1-workspace-agent-operations-design.md` for milestone **v0.26.1** ("Workspace-Agent Charter and Role Operations", Release Epic #2469, Parent #2458).

Every task adheres to strict **Test-Driven Development (TDD)**:
1. **Red:** Author or expand failing verification/regression tests.
2. **Green:** Implement surgical production changes conforming to modular boundaries.
3. **Refactor & Verify:** Execute focused test suites under sandbox isolation (`SYNLYNK_REGISTRY_PATH=/tmp/test_synlynk_reg.json`).

---

## Task Breakdown

### Task 1: Charter Schema Expansion & JSON Retirement (gh:#2305)
- **Domain:** Content, Documentation & Architecture (`synlynk/charter_schema.py`, `synlynk/charters.py`, `synlynk/agent_store.py`)
- **Recommended Harness:** Agy (`gemini-2.5-pro` / `gemini-1.5-pro`) or Codex (`gpt-5.6-sol`, `--force-harness`)
- **Files to Modify:**
  - `synlynk/charter_schema.py`: Expand frontmatter schema (v2.0) with `mandate`, `autonomous_authorities`, `escalation_triggers`, `sops`, `verification_contracts`.
  - `synlynk/charters.py`: Update `load_charter()`, `validate_charter()`, and `drift_status()` to parse Markdown frontmatter directly; deprecate dead `.json` paths.
  - `tests/test_charter_schema.py`: Add schema validation test cases.
  - `tests/test_charters.py`: Add drift and adaptation tests without JSON files.
- **Implementation Steps:**
  1. In `tests/test_charter_schema.py`, create tests asserting:
     - Schema 2.0 validates required fields (`schema_version`, `role`, `description`, `durability`, `tools`, `credentials`).
     - Optional fields (`mandate`, `autonomous_authorities`, `escalation_triggers`, `skills`, `sops`, `verification_contracts`) parse into typed structures.
     - Invalid schemas raise `CharterValidationError` with specific error details.
  2. In `tests/test_charters.py`, assert that `load_charter()` and `drift_status()` function seamlessly by reading YAML frontmatter from `.synlynk/agents/`, verifying `.synlynk/charters/*.json` is no longer required.
  3. In `synlynk/charter_schema.py`, expand `parse_frontmatter()` and `validate_frontmatter()` to support the 2.0 schema fields.
  4. In `synlynk/charters.py`, refactor `load_charter()` and `adapt()` to read and mutate Markdown frontmatter.
  5. Run `pytest tests/test_charter_schema.py tests/test_charters.py`.

### Task 2: Superpowers Skill Binding & Post-Flight Gate (gh:#2305)
- **Domain:** CLI Plumbing & Dispatch Runtime (`synlynk/charter_injection.py`, `synlynk/dispatch.py`, `synlynk/jobs.py`)
- **Recommended Harness:** Codex (`gpt-5.6-sol`, `--force-harness`) or Agy
- **Files to Modify:**
  - `synlynk/charter_injection.py`: Render binding superpowers skill directives.
  - `synlynk/dispatch.py`: Inject rendered superpowers into dispatch prompt headers.
  - `synlynk/jobs.py`: Add post-flight verification check on job reconciliation.
  - `tests/test_charter_injection.py`: Verify skill prompt injection.
  - `tests/test_jobs.py` / `tests/test_dispatch.py`: Verify post-flight verification gate.
- **Implementation Steps:**
  1. In `tests/test_charter_injection.py`, assert that when a role charter includes `skills: [test-driven-development, systematic-debugging]`, `render_charter_section()` outputs explicit `[MANDATORY SKILL CONTRACT: ...]` blocks containing strict non-negotiable clauses.
  2. In `synlynk/charter_injection.py`, add skill clause templates for `test-driven-development`, `systematic-debugging`, and `brainstorming`.
  3. In `synlynk/jobs.py` (`_reconcile_daemon_jobs` / `_reconcile_jobs_unlocked`), if a job's task contract requires tests (`verification_contracts`), verify that git changes in the task worktree include test files. If absent, record status as `FAILED_VERIFICATION`.
  4. Run `pytest tests/test_charter_injection.py tests/test_jobs.py`.

### Task 3: Autonomous Maintainer Role Charter & Sentinel Triage Loop (story-2e48a8c5)
- **Domain:** Subsystems & Telemetry (`synlynk/maintainer.py`, `synlynk/sentinel.py`, `synlynk/daemon.py`, `synlynk/cli.py`)
- **Recommended Harness:** Agy (`gemini-2.5-pro` / `gemini-1.5-pro`) or Codex (`gpt-5.6-sol`, `--force-harness`)
- **Files to Modify:**
  - `synlynk/maintainer.py`: Implement alert grouping, fingerprinting, and triage issue generation.
  - `synlynk/cli.py`: Add `synlynk maintainer triage` and `probe` commands.
  - `synlynk/daemon.py`: Hook Maintainer pass into `_autonomy_pass()`.
  - `.synlynk/agents/maintainer.yaml`: Register canonical Maintainer charter.
  - `tests/test_maintainer.py`: Add triage and issue generation tests.
- **Implementation Steps:**
  1. Create `tests/test_maintainer.py`:
     - Test parsing and grouping of compacted sentinel entries from `.synlynk/sentinel.md`.
     - Test grouping by error fingerprint and calculation of recurrence counts.
     - Test formatting of reproduction issue markdown (Intent, Context, Reproduction Recipe).
     - Test CLI output for `synlynk maintainer triage`.
  2. In `synlynk/maintainer.py`, implement:
     - `triage_sentinel_alerts(max_age_days=7)`: Parse, deduplicate, and rank recurring alert groups.
     - `format_triage_issue(fingerprint_group)`: Generate standardized GitHub issue body.
     - `probe_reproduction(fingerprint_group, workspace_root)`: Prepare scratch worktree and execute verification probe.
  3. In `synlynk/cli.py`, expose `maintainer triage` and `maintainer probe`.
  4. Register `maintainer` role in `.synlynk/agents/` using schema 2.0.
  5. Run `pytest tests/test_maintainer.py tests/test_sentinel.py`.

  - `synlynk/claims.py`: Protect active claims with atomic file locks.
  - `synlynk/context.py`: Implement scoped file list generation for AST scans.
  - `tests/test_dispatch_preflight_hardening.py`: Add preflight isolation and cleanup tests.
- **Implementation Steps:**
  1. In `tests/test_dispatch_preflight_hardening.py`:
     - Test that orphaned dead-PID worktree directories in `.worktrees/` are pruned prior to branch creation (#2185).

     - Test that `--task-type review` is checked against capacity limits without regex false positives (#2233).
     - Test that context assembly for sub-3k token tasks restricts scanned paths (#2133).
  2. In `synlynk/dispatch.py`, update preflight checks to prune dead-PID worktrees and honor `--task-type`.
  3. In `synlynk/claims.py`, implement atomic file locking for claim operations.
  4. In `synlynk/context.py`, add path-scoped filtering.
  5. Run `pytest tests/test_dispatch_preflight_hardening.py tests/test_worktree.py`.
