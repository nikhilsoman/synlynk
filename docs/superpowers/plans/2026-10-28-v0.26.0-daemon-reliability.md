# v0.26.0 — Daemon reliability Implementation Plan

## Overview

This implementation plan translates the design specification in `docs/superpowers/specs/2026-10-28-v0.26.0-daemon-reliability-design.md` into concrete, test-driven implementation tasks.

Every task follows strict Test-Driven Development (TDD):
1. **Red:** Write or verify a failing regression test covering the edge case.
2. **Green:** Implement the surgical fix adhering to modular packaging and typing standards.
3. **Refactor & Verify:** Execute the focused pytest suite under sandbox isolation.

---

## Task Breakdown

### Task 1: Daemon Stop Idempotence & State Truth (gh:#2464)
- **Domain:** CLI Plumbing & Core Subsystems (`synlynk/daemon.py`, `synlynk/watch.py`)
- **Recommended Harness:** Codex (`gpt-5.6-sol`, `--force-harness`) or Agy
- **Files to Modify:**
  - `synlynk/daemon.py`: Refactor `SynlynkDaemon.stop()` and `WatchDaemon.stop()`.
  - `synlynk/watch.py`: Align CLI stop command outputs.
  - `tests/test_daemon_lifecycle.py` / `tests/test_synlynk.py`: Add multi-stop idempotent assertions.
- **Implementation Steps:**
  1. In `tests/test_synlynk.py`, expand `test_synlynk_daemon_stop_idempotent` to assert:
     - Turn 1 on running daemon: outputs `✓ synlynk daemon stopped.`
     - Turn 2 on stopped daemon: outputs `✦ daemon not running`
     - Turn 3 on unstarted daemon: outputs `✦ daemon not running` with returncode 0.
  2. In `synlynk/daemon.py`, ensure `_resolve_live_pid()` only returns a PID if `_pid_is_alive(pid)` is true AND verified against the daemon's own identity.
  3. Ensure `_cleanup_stale_pidfile()` and lock release operate under non-blocking lock acquisition, eliminating race conditions.
  4. Run `SYNLYNK_REGISTRY_PATH=/tmp/test_synlynk_reg.json pytest tests/test_synlynk.py -k test_synlynk_daemon_stop_idempotent`.

### Task 2: macOS Fork-Safety & Canonical Absolute PEM Lookup (gh:#1884)
- **Domain:** Authentication & Platform Security (`synlynk/github_app_auth.py`, `synlynk/daemon.py`)
- **Recommended Harness:** Codex (`gpt-5.6-sol`, `--force-harness`)
- **Files to Modify:**
  - `synlynk/github_app_auth.py`: Fix `_resolve_private_key_path()` and `_default_apps_dir()`.
  - `tests/test_github_app_auth.py`: Add CWD-shifted private key resolution test cases.
- **Implementation Steps:**
  1. In `tests/test_github_app_auth.py`, create a test that changes current working directory into a nested temporary subdirectory and attempts `_resolve_private_key_path()`. Verify it resolves to the absolute canonical path in `~/.synlynk/product_store` or workspace root, not a dead CWD-relative path.
  2. In `synlynk/github_app_auth.py`, replace fallback relative paths with `resolve_github_apps_dir()` and `state_db_path()` lookups.
  3. In `_sign_jwt()`, set `close_fds=True` and ensure environment passes `OBJC_DISABLE_INITIALIZE_FORK_SAFETY=YES` to child `openssl` invocations.
  4. Run `pytest tests/test_github_app_auth.py`.

### Task 3: Repair Scratch Cleanup Active Selftest Isolation (gh:#2407)
- **Domain:** Diagnostics & Workspace Management (`synlynk/doctor.py`)
- **Recommended Harness:** Codex (`gpt-5.6-sol`, `--force-harness`)
- **Files to Modify:**
  - `synlynk/doctor.py`: Harden `cleanup_selftest_workspaces()`.
  - `tests/test_selftest_isolation.py`: Add concurrency and active-lease protection tests.
- **Implementation Steps:**
  1. In `tests/test_selftest_isolation.py`, verify that `cleanup_selftest_workspaces()` leaves active PID workspaces intact even if mtime is simulated past 1 hour.
  2. In `synlynk/doctor.py`, enforce:
     - Active PID check: `kill(pid, 0)` must fail with `ProcessLookupError` before deletion is attempted.
     - Grace period: Unowned or unreadable directories must have mtime > 600s before deletion.
  3. Run `pytest tests/test_selftest_isolation.py tests/test_doctor.py`.

### Task 4: Live Command Selftest Real-Launch Coverage (gh:#422)
- **Domain:** Testing & Verification Contracts (`synlynk/selftest.py`)
- **Recommended Harness:** Grok (`grok-4.6`, `--force-harness`) or Agy
- **Files to Modify:**
  - `synlynk/selftest.py`: Add `_scenario_watch()` and `_scenario_viz()`.
  - `tests/test_selftest.py`: Assert real scenarios are dispatched for `watch` and `viz`.
- **Implementation Steps:**
  1. In `synlynk/selftest.py`, create `_scenario_watch`:
     - Spawns subprocess for `synlynk watch` with isolated scratch config.
     - Reads initial output stream within 2.5 seconds.
     - Sends `SIGTERM`, verifies process terminates cleanly (exit 0) and unlinks its pidfile.
  2. In `synlynk/selftest.py`, create `_scenario_viz`:
     - Spawns `synlynk viz daemon start` on a random ephemeral port.
     - Validates HTTP status 200 on `/health` or UI index.
     - Calls `synlynk viz daemon stop` and verifies socket release.
  3. Register both in `SELFTEST_SCENARIOS`.
  4. Run `pytest tests/test_selftest.py`.

### Task 5: Sentinel Alert Aging, Deduplication & Compaction (`story-a4442387`)
- **Domain:** Observability & Telemetry (`synlynk/sentinel.py`, `synlynk/platform_ops.py`)
- **Recommended Harness:** Grok (`grok-4.6`, `--force-harness`) or Agy
- **Files to Modify:**
  - `synlynk/sentinel.py`: Implement `compact_sentinel_alerts()`.
  - `tests/test_sentinel.py`: Add compaction, TTL expiry, and malformed line sanitization tests.
- **Implementation Steps:**
  1. Write unit tests in `tests/test_sentinel.py` asserting:
     - Alerts older than 30 days are pruned.
     - Duplicate alerts within 24 hours are consolidated with incremented `occurrences` count.
     - Unparseable lines (argparse usage snippets) are sanitized and stripped.
  2. Implement `compact_sentinel_alerts()` in `synlynk/sentinel.py` and hook it into the periodic sentinel pulse or `synlynk status` path.
  3. Run `pytest tests/test_sentinel.py`.
