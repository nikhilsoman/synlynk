Launch HN: Synlynk (v0.29.0 Dev Preview) — The Full-Stack Builder Harness

Hi Hacker News,

I’m Nikhil, and for the past five months I’ve been building Synlynk (https://github.com/nikhilsoman/synlynk). Today we’re releasing the v0.29.0 Developer Preview under the Apache 2.0 license.

The Problem with Solo Building in the Agentic Era

When building non-trivial software today, single developers face a brutal cognitive bottleneck: you have to be the Product Manager, Software Architect, Tech Lead, Backend Dev, Frontend Dev, and QA Engineer simultaneously.

Most AI developer tools today give you a single monolithic chat window or an autonomous coding agent with a bash shell. While impressive for small scripts, they break down on 10,000+ line codebases because:

  1. Chat windows don't have role separation: An agent writing code shouldn't be the same agent approving its own architecture or certifying its own test coverage.
  2. Context degradation is real: Throwing an entire repo into a 1M token context window leads to subtle hallucinations, silent regressions, and massive token burn.
  3. No verifiable contracts: Most agents claim a task is "done" when the code is written, regardless of whether tests actually pass or regressions were introduced.

The Two Paradigms Synlynk Explores

Synlynk started as an experiment to explore two emerging paradigms in software engineering:

  1. Paradigm 2a (The Full-Stack Builder): A single human engineer with specific core competencies can assemble a specialized digital team (PM, Architect, TPM, Dev, QA, Maintainer) to fill all other functional voids and build complete, production-grade products.
  2. Paradigm 2b (The Autonomous Organisation): An engineering organization emerges from high-level policy directives, goals, and budgets—autonomously leasing whatever resources (cloud compute, model APIs, human sign-off gates) are needed to execute verified deliverables.

We believe you cannot achieve 2b without first mastering the atomic unit of collaboration in 2a. That’s what this Developer Preview is designed to test with you.

What Synlynk Does

When you install Synlynk and run synlynk new in a blank directory (or synlynk onboard in an existing repo):

  • Multi-Harness Execution: Synlynk doesn’t lock you into one model provider. It orchestrates Claude, OpenAI/Codex, Google Gemini/Agy, and Grok—dynamically routing tasks to whichever engine has proven highest empirical capability for that specific domain.
  • The GOVERNS SDLC: Your fleet moves through an explicit lifecycle:
    1. PM: Synthesizes your intent into a crisp Executive Brief and Goal 1.
    2. Architect: Generates a formal design spec and isolates genuine architectural dilemmas.
    3. DECIDE Panel: Convenes multiple AI engines (e.g. Claude + Codex + Grok) to debate the trade-offs live and record a signed decision.
    4. TPM: Breaks the approved spec into atomic, dependency-ordered tasks.
    5. Dev & QA: Execute test-driven development (TDD) in isolated worktrees with non-author verification before merge.
  • The Synlynk Invariants (Inspired by Asimov's Laws):
    • Invariant 0: The fleet will never leak secrets or compromise system integrity.
    • Invariant 1: The human operator holds sole sovereign authority.
    • Invariant 2 (Evidence Over Assertions): No task or bugfix is marked complete without passing tests and diff proofs.
    • Invariant 3: Token burn and quotas are strictly metered against hard budgets.
  • Companion v2.1: An ambient co-pilot that surfaces 4-part task boundaries ([Signal], [Context], [Nudge], [Deep Links]) with clickable terminal hyperlinks into your local Vizor observatory (http://localhost:33333) and GitHub PRs.

Why Developer Preview?

We have no monetization motive today. Our objective is to put Synlynk into the hands of real builders, see whether our hypotheses hold across diverse tech stacks, and learn where the human-machine boundary needs refinement.

Getting Started (5 Minutes)

# Install via pipx (recommended) or pip
pipx install synlynk

# Start a brand new project with your synthetic team
synlynk new "your-project-name"

# Or onboard an existing repository
cd existing-repo && synlynk onboard

The repo is open source (Apache 2.0): https://github.com/nikhilsoman/synlynk

We'd love your feedback, critiques, and stories on how your fleet performs!
