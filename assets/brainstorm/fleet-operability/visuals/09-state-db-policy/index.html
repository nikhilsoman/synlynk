Block 3 — Nested state.db policy

Doctor will FAIL if nested copies exist. What should runtime do when a job tries to create one?

A

Hard error + refuse (recommended)

Jobs must use the canonical ~/.synlynk/projects/<key>/state.db (or explicit env override). Creating .synlynk/state.db under a job worktree is an error after migration period, not a silent fallback — except the #650 sandbox fallback which is documented as empty/local-only and never the product ledger.

B

Warn + redirect to canonical

Always open canonical path; log warning if nested file exists. Softer; nested files can linger as zombies.

C

Quarantine + auto-delete nested on doctor

Doctor removes nested DBs (or moves to trash). Aggressive; risk of deleting intentional local scratch.
