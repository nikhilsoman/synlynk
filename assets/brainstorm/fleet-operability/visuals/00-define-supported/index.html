Block 0 — What does “supported” mean?

This is the gate definition. Everything else (fleet list, doctor severity, matrix gate) hangs off this one sentence.

Context

The decide panel was unanimous: full-fleet operability is not completely supported today. Before we design the fix, we need a product definition that CI and doctor can enforce — not a vibes-based marketing claim.

A

CLI on PATH

A harness is “supported” if its binary is installed and invokable. Lightest bar. Matches today; allows false-greens forever.

B

Doctor green

Supported = all TC checks pass for that agent (flags, network, SOP, etc.). Stronger than A, but still can be presence-only if TCs stay soft.

C

Weekly green live matrix

Supported = last live home×target matrix cell passed (exit + cost/files + side-effects). Only true proof. Costs $ and needs a runner.

D

Tiered (recommended)

Supported = doctor FAIL-closed green + last dry matrix green. Proven = plus live matrix within N days. Docs never claim more than the tier.

Why D is recommended

  • Matches panel synthesis: stop advertising unproven claims
  • Lets daily CI stay cheap (dry) while live proof is scheduled
  • Gives language for “experimental” (local, codex GH-write)

Tradeoffs

  • Two words to maintain (Supported vs Proven)
  • Requires matrix runner to exist before “Proven” means anything
  • Still need to define which TCs are FAIL vs warn
