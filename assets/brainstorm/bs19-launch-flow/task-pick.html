User picks a task — what happens next?

After pressing [1] for "Workspace architecture review"

A

Instant dispatch — job starts immediately

Pressing [1] fires synlynk dispatch claude --task "..." --context-mode full right away. A job ID prints and synlynk exits. User checks progress with synlynk jobs.

▶ [job-a3f2c1] claude dispatched  PID 44821
Log: synlynk logs --job job-a3f2c1
✓ Zero friction — one keypress to running job
✗ No chance to add context or pick a different agent
B

Quick confirm — shows what will be dispatched, then fires

A compact preview screen shows the task prompt, assigned agent, estimated duration, and cycle tag. User presses [enter] to confirm or [e] to edit the prompt before dispatching.

patterns, tech debt hotspots, and improvement areas...

✓ User sees exactly what's going to the agent
✓ Escape hatch to edit before committing
✗ One extra keypress
C

Mini-wizard — configure agent, scope, output before dispatching

Opens a 3-step sub-flow: pick agent (defaults to Claude for Dream tasks) → set context mode (none/task/full) → confirm. More control, more friction.

◆ Configure task [1/3]

✗ Too much friction for "just get me started" intent
