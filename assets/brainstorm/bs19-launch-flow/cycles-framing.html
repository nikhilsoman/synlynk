The 6 Cycles — which framing fits?

Both have 6 stages. The difference is whether "Design/Brainstorm" is its own cycle or absorbed into Plan.

Option A — Current model (Dream · Plan · Work · Ship · Maintain · Engage)
1
Dream
What's worth building? Fix a bug, refactor, modernise a feature
2
Plan (absorbs brainstorm + spec)
Brainstorm → spec/UX → break into stories → assign agents
3
Work
Dispatch agents, run jobs, review diffs, iterate
4
Ship
Cut release, changelog, publish
5
Maintain
Monitor, patch, keep the lights on
6
Engage
Users, community, docs, support
✓ Already in codebase · cycle_capability table uses these names · less disruption
Option B — Explicit Design cycle (Dream · Design · Plan · Build · Ship · Sustain)
1
Dream
What's worth building? Fix a bug, refactor, modernise a feature
2
Design (new explicit stage)
Brainstorm → spec → UX/wireframe → agent roles for this feature
3
Plan
Implementation plan, story breakdown, wave schedule
4
Build
Dispatch agents, run jobs, review diffs, iterate
5
Ship
Cut release, changelog, publish
6
Sustain (Maintain + Engage combined)
Monitor, patch, community, docs, support
